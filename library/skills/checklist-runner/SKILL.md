# Checklist runner

## How to run one

Work down the list, one item at a time. For each: **done · not applicable ·
missing**, with the evidence for anything marked done — a file name, a
reference, a date. A tick with no evidence is a promise, not a record.

Never mark an item done because it usually is. If it has not been seen, it is
missing.

## What to hand back

A short report:

1. what is missing, first, because that is the only part anybody acts on
2. what is not applicable and why
3. what is complete, with evidence

## Making a new checklist

If the user does not have one yet, build it from what they describe, show it
to them, and save it once they agree. A checklist somebody has not agreed to
is a checklist that gets ignored.

## The habit worth keeping

Date and sign every run. The value of a checklist is mostly in being able to
say, later, that it was run — and when, and against what version.
