# Client and case file keeper

A file that is only current in somebody's head is not a file. This keeps the
project's own summary honest, so that anybody — including the user in three
months — can pick it up.

## What to keep

For each job, four short things and nothing more:

- **state** — where it stands now, in three lines. Rewritten, not appended.
- **actions** — what is owed by us, with who and when.
- **waiting** — what is owed *to* us, with who and since when.
- **history** — dated one-liners of what actually happened. Append only.

## When to update

When something changes: a decision, an instruction, a submission, a payment,
a promise made. Update at the time, not at the end of the week — a summary
reconstructed later is a summary of what somebody remembered.

## Rules

- **State is rewritten; history is never rewritten.** If something turned out
  to be wrong, add a line saying so with today's date. Editing the past makes
  the record useless as evidence.
- Say who said it. "Client agreed" is not a record; "Client (Mr Chan, phone,
  14 Aug) agreed" is.
- Keep it short enough to be read on a phone.
